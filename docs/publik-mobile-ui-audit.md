# Публик: мобильный UI/UX

## Цель и границы

Аудит от 25 сентября 2026 года: каталог чатов и каналов, нижняя навигация,
модули получателя, посты, расписания, история, редактор, выбор получателей,
кнопки и автоответы. Приоритет: доступность действий на мобильном экране,
предсказуемая прокрутка и читаемость, без изменения API и правил публикации.

Браузерные проверки используют локальные preview-данные и безопасный MAX Bridge shim.
Они не являются проверкой реальных разрешений, отправки постов или поведения всех
версий нативного MAX. Утверждать отсутствие всех возможных ошибок по эмуляции нельзя.

## План реализации

1. Исправить геометрию каталога и навигации без глобального запрета прокрутки.
2. Сохранить серверные фильтры и cursor pagination; устранить сбои большого списка.
3. Уточнить типографику, цветовые роли, доступность поиска и состояний.
4. Проверить обычный и большой каталоги, пустое состояние, ошибки, клавиатуру,
   поворот экрана и переход «Посты → Чаты» после загрузки CSS соседнего маршрута.
5. Проверить соседние экраны Публика и регрессию Майора, выполнить production build.
6. Доставить только `miniapp-major-static` после обязательного exact-SHA CI и штатных smokes.

Пункты 1–3 реализованы в scoped CSS Публика, Shell и PublisherEntitiesPage.
Автоматизация пункта 4 находится в
`apps/miniapp/test/publisher-catalog-layout.browser.mjs`; существующий screenshot harness
покрывает соседние экраны и проверяет контраст, доступные имена и геометрию.

## Приёмка

- `npm run check:miniapp`
- `npm run build:miniapp:production`
- `node apps/miniapp/test/publisher-catalog-layout.browser.mjs`
- Строгие screenshot-сценарии Публика: iPhone SE/light и Android/dark.
- Каталог: 320×480, iPhone SE, iPhone 15 с нижним safe area, Pixel 7 и desktop,
  обе темы, 200 записей, переход к виртуализации, поворот и уменьшение visualViewport.
- Последняя строка должна быть доступна реальному hit testing; одна только
  проверка наличия элемента в DOM не доказывает отсутствие перекрытия.
- Физические устройства: отдельно проверить iOS/Android MAX, свайп до последнего
  сообщества, клавиатуру поиска, системное увеличение текста, VoiceOver/TalkBack.

## Дальнейшее развитие

Следующие улучшения требуют подтверждения пользовательскими сценариями, а не
добавления новых декоративных блоков:

- Проверить время поиска нужного сообщества на каталогах 10/100/200 записей;
  оценивать избранное или закрепление только если поиск и разделение по типу недостаточны.
- Провести ручной аудит увеличенного системного шрифта и экранных дикторов
  на реальном MAX, включая виртуальный список и редактор.
- Проверить нестабильную сеть и восстановление доступа на тестовом подключении
  с настоящим API, не публикуя сообщения в пользовательские каналы.
- Сохранять размер startup bundle и число запросов; новые анимации, библиотеки
  или фоновые опросы должны решать измеримую проблему.

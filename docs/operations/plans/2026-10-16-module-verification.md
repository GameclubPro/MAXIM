# Проверка модулей каналов и чатов

Поручение владельца от 16 октября: закончить текущее исправление, затем проверить
каждый модуль каналов и чатов, исправляя воспроизводимые ошибки. Отдельные жалобы:
пропускаются кнопки под публикациями и неверно считается длина поста.
Это продолжение [общего плана](2026-10-15-bot-optimization-final-plan.md),
а не заявление о завершённой проверке.

## Порядок

1. Завершить изоляцию ошибок резервного обхода и восстановления действий под
   публикациями: профильные тесты, реальные PostgreSQL/Redis, exact-SHA CI,
   штатный выпуск всех ролей общего API-образа и сравнение после выпуска.
   Действующий backup/deploy-lock сохраняется. Исторические незавершённые
   источники разбираются отдельно по точному preview.
2. Составить полный перечень модулей по текущим настройкам, контрактам, интерфейсу
   и реально зарегистрированным обработчикам. Для каждого указать владельца
   (Майор/Публик), включение, входное событие, ожидаемый эффект и способ проверки.
   Отсутствие логов или выключенный модуль не записывать как успешную проверку.
3. Проверить каналы, начиная с действий под постами; затем чаты, начиная с
   подсчёта символов. При новой доказанной production-регрессии исправлять её
   приоритетно, не открывая несколько конкурирующих выпусков.
4. Каждый подтверждённый дефект воспроизвести тестом, исправить, проверить
   затронутые вызовы/границы и доставить штатным процессом. Не смешивать
   наблюдение, локальную проверку, CI, выпуск и принятую работу в MAX.

## Матрица сценариев

| Область                  | Что проверить                                                                                                                                                                                                                        |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Действия канала          | Подпись, комментарии, предложения, быстрые кнопки; одиночные и совместные настройки; обычный текст, фото/альбом, видео, пересылка; сохранение ссылок, форматирования, медиа и существующих кнопок                                    |
| Полнота действий         | Исходный пост → webhook → сохранённая задача → запрос → подтверждённое изменение. Проверять также посты, для которых маркер вообще не создан; успешность только существующих маркеров недостаточна                                   |
| Обновление постов        | Редактирование/удаление до и после обработки, выключение функции, смена настроек, повторные webhook, разные боты, перезапуск, параллельное обновление одного поста                                                                   |
| Опросы и взаимодействие  | Создание, кнопки/голосование, обновление результата, завершение, повтор callback, исходный бот старого объекта, потеря доступа, неоднозначный 404                                                                                    |
| Публик                   | Немедленные/отложенные публикации, предложения, комментарии, импорт/VK и расписания в собственном домене. Проверять сроки, повтор после ожидания и неизвестный SEND отдельно; не передавать его права Майору                         |
| Длина сообщения          | Границы N−1/N/N+1; кириллица/латиница, эмодзи вне BMP, составные эмодзи, диакритика, CRLF/LF, пробелы, ссылки и разметка, подпись к медиа, пересланный текст. Сопоставить счётчик интерфейса, backend и фактически проверяемый текст |
| Прочие фильтры чата      | По полному перечню настроек: ссылки/телефоны/стоп-слова, спам, дубликаты текста/фото, медиа/голосовые, подписки, OCR. Проверить исключения администратора, включение/выключение, совместные нарушения и отсутствие повторных санкций |
| Команды и состояние чата | Старт, правила, ручные санкции, муты, закрытие/ночной режим, расписания, сообщения о результате. Сроки и актуальные права проверять перед действием; команды не должны повторять неизвестные старые эффекты                          |
| Несколько ботов          | Повторные доставки, доказанный действующий исполнитель, исходный бот старых кнопок/опросов, отзыв/возврат прав через явную активацию, независимый прогресс других чатов при cooldown одного бота                                     |
| MAX и зависимости        | 429/Retry-After, таймаут до/после отправки, 5xx, неверный/неполный ответ, неизвестные права, Redis/PostgreSQL и перезапуск. Сохранять неизвестные эффекты, дедлайны и запреты                                                        |

Для длины сначала зафиксировать проверяемое значение «символ»: текущая семантика
должна быть одинаковой в интерфейсе и правиле. Не подменять её количеством байтов,
HTML-разметки или длиной UTF-16 без проверки пользовательского поведения.
Изменение семантики требует общей функции подсчёта, граничных регрессий и проверки
отложенных действий; не применять новый подсчёт к старым санкциям задним числом.

## Реальные проверки и приёмка

Назначены владельцем: чат `-78271094414679`, канал `-78271171091799`.
Перед сценарием подтвердить реальный тип и свежие права конкретного бота.
Создавать только явно помеченный тестовый контент, удалять только его и
восстанавливать настройки сценария. В остальных сообществах использовать
ограниченное чтение и фактические включённые действия продукта; не отправлять
диагностику и не переписывать старые публикации ради проверки.

По каждой строке сохранять результат, время, исходную версию, подтверждение
внешнего эффекта и непроверенные случаи. «Все модули проверены» возможно только
после закрытия полного перечня, а не одной публикации или успешного health.
Независимая оценка качества фильтров остаётся отдельным открытым условием:
владелец сообщил, что размеченного набора и рецензентов пока нет.

Общая приёмка сохраняет проверку восстановления данных, нагрузки и реального
пика. Финальные непрерывные 30 минут начинаются после остальных условий и
последнего изменения; исправление, ошибка или разрыв наблюдения обнуляют окно.

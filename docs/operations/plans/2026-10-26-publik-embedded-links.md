# Публик: сохранение вшитых ссылок — 26 октября 2026

## Воспроизведённые причины

В редакторе создать ссылку без выделения, применить URL и заменить выделенный
«текст ссылки» своим названием. Нативный `contentEditable` удалял `<a>` при полной
замене названия; внутри предложения иногда ссылкой оставалась только первая буква.
Браузерная регрессия на исходной реализации получила `Read more` вместо
`[Read more](https://example.com/article?source=publik&read=1)`.
Сохранение и публикация уже получали текст без адреса.

Второй сценарий: выделить обычный текст вместе с существующей ссылкой и применить
новый URL. Редактор создавал вложенные `<a>` и некорректный Markdown. После открытия
черновика новый адрес терялся, а часть разметки становилась видимым текстом.

Путь обычной HTTPS-ссылки в API проверен отдельно: Publication сохраняет Markdown,
подготовка преобразует его в HTML anchor, MAX получает `format: html`.
Обновление клавиатуры передаёт `text: null`, сохраняя текст поста. HTML-ссылки
поддержаны [официальной документацией MAX](https://dev.max.ru/docs-api/use-cases/sending-messages/text-formatting).
Дефект этой жалобы воспроизведён до отправки запроса публикации.

## Исправление

Полная замена названия сохраняет ссылку при обычном наборе, составном вводе и
многосимвольной вставке. Пустая служебная граница не содержит скрытых символов,
не сериализуется и удаляется при потере фокуса. Для полной многосимвольной замены
используется нативная HTML-вставка с историей Undo/Redo, экранированным текстом,
сохранением семантических стилей и восстановлением курсора.
Отказ нативной команды оставляет исходный ввод разрешённым.

Замена относится только к полностью выделенному названию ссылки. Совпадение текста
при частичном пересечении недостаточно: проверяются обе границы выделения.
Назначение нового адреса всему фрагменту удаляет вложенные ссылки, сохраняя их
видимый текст и форматирование. Проверка допустимых URL остаётся общей для ввода,
буфера и редактора.

## Проверки и границы доказательства

`max-rich-text-formatting.browser.mjs` проверяет создание и переименование ссылки,
кириллицу/эмодзи, вставку, составной ввод Chromium, autocorrect target ranges,
Undo/Redo, повторное открытие, изменение адреса, сохранение жирного оформления,
HTML-экранирование, отказ нативной команды и частичное пересечение `aa[aa]`.
Сценарии проходят на desktop/iPhone/Android размерах в светлой и тёмной темах.

`publication-composer-usability.browser.mjs` проверяет настоящую форму, получателя,
проверку поста и запрос публикации с переименованной ссылкой. Обе попытки после
обновления доступа сохраняют одинаковый Markdown и URL; служебные DOM-атрибуты
не попадают в запрос. Проверены восемь сочетаний размера и темы, включая iPhone SE.

Это локальный Chromium с эмуляцией размеров и составного ввода. Autocorrect
моделирует событие с диапазоном замены. MAX HTTP в этой проверке не вызывается;
публикации в пользовательские сообщества не выполняются. Проверки CI, выпуск и
прочтение активного компонента являются отдельными этапами доставки.

# Завершение процесса при отмене загрузки медиа

16 октября в `07:45:37.947Z` процесс `api-media-analysis` завершился с необработанным
`AbortError`. Образ: `sha256:55e4567be84aac1d9438ff1bf15bddd0278a02de52916e089bec8566098850b6`,
исходная версия: `a9740f7ad0e644ad07a76f06ad7c6f666b690bc2`. Docker запустил тот же
контейнер снова в `07:45:38.199Z`; к `07:48:48Z` его счётчик перезапусков равнялся
одному, остальные 13 API-ролей — нулю. Это подтверждённый сбой процесса, а не
штатное завершение модерации. Повтор неизвестных внешних действий не выполнялся.

Стек ведёт из `SecurePhotoDownloader.requestWithValidatedAddressFallback` через
отмену Node-запроса. Его помощник `withDeadline` получал уже запущенный Promise,
но проверял оставшееся время до подключения обработчиков `Promise.race`.
Если срок истекал в этом промежутке, исходный Promise оставался без обработчика.
Последующая отмена запроса завершала процесс. Такой же дефект затрагивал поздние
ошибки DNS и чтения тела ответа.

Отдельные процессы Node с `--unhandled-rejections=strict` воспроизвели все три
варианта для `download` и `downloadBinary`: шесть падений до исправления.
Для запроса используется настоящий `ClientRequest` с незавершаемым тестовым DNS,
без сетевого соединения. Проверяется также отказ для уже полученного ответа
после дедлайна и успешная следующая загрузка тем же экземпляром.

Проверка срока теперь выполняется внутри Promise таймера; даже немедленный отказ
участвует в `race` вместе с запущенной операцией. Promise дедлайна расположен
первым, поэтому истёкший срок сохраняет приоритет над уже готовым результатом.
Глобальных обработчиков подавления ошибок нет. Общий deadline, отмена запроса,
лимиты параллельности/байтов, проверка адресов и политика модерации сохраняются.
Пересоздана только генерируемая идентичность runtime OCR; scoring не менялся.

Локально: 236 профильных тестов и 145 проверок зависимых путей, включая настоящие
PostgreSQL/Redis. Это не production-приёмка. После штатного выпуска нужны свежие
когорты, независимые результаты действий и наблюдение перезапусков.
Отдельный `native_timeout` OCR-сандбокса в `07:56:40Z` этим исправлением не устранён.

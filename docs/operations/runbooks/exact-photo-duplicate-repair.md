# Точные повторы фото в антидубле

## Границы

Рабочий путь: `message-duplicates`, runtime `full`, настройка
`antiDuplicateEnabled=true` и `duplicateCompareMode=MESSAGE`.
Фото без подписи тоже является сообщением. Сравнение выполняется у одного участника
в одном чате; подпись, ссылки, кнопки и полный набор вложений входят в сравнение.
Изменённая подпись или неполный альбом не обещаются как точный повтор сообщения.

Для строгого сценария «вторая публикация удаляется» настройка «Разрешить дублей»
должна быть `0`. Оригинал не считается дублем. Значение `1` намеренно оставляет
первый повтор и начинает удаление с третьей публикации; существующие допуски
администраторов не сбрасываются при выпуске исправлений. Новые настройки сейчас
также имеют допуск `1`, а не строгий `0`.

Это не включение экспериментального фотофильтра: его `shadow`, область `CHAT`
и поиск похожих изображений остаются отдельной политикой. Настройки чатов,
лимиты ресурсов и разрешённые хосты не меняются автоматически.

## Оптимизированный Порядок

1. Webhook сохраняет проверяемый источник и ставит компактную задачу в очередь.
   В Redis и заданиях нет исходных изображений, подписей или ссылок скачивания.
2. Первое вхождение сохраняет указатель без скачивания. Потенциальный повтор
   запускает проверку пары в фоновом worker с concurrency 2.
3. Используются готовые отпечатки; отсутствие ID у одного элемента альбома
   не отключает кеш остальных. Скачиваются только отсутствующие элементы.
4. Если ссылка на фото отсутствует или отвечает 403/404/410, выполняется один
   точечный запрос исходного сообщения к MAX. Проверяются чат, сообщение, автор,
   подпись, ссылки, кнопки и идентификаторы вложений. Обновлённый источник всё равно
   проходит защищённое скачивание и вычисление отпечатка. Один ID не доказывает дубль.
5. Временный сбой проверки исходного вхождения повторяет задачу, не теряя исходную
   историю. Неподдерживаемый формат не получает бесполезных повторных декодирований;
   нехватка слотов декодера вызывает ограниченную отсрочку.
   Указатель на само текущее сообщение означает возможное незавершённое действие,
   а не новое первое вхождение. После сбоя сохранения intent задача заново проверяет
   историю и продолжает удаление, даже если кеш отпечатка был вытеснен.
   Проверенный обновлённый источник кешируется также под исходной ссылкой webhook.
   Готовые отпечатки читаются один раз и позволяют завершить действие без повторного
   декодирования, даже когда тяжёлая обработка изображений приостановлена.
   Для новых пар используется `allowRecoveryWindowRun`: окно стабилизации само по
   себе не останавливает проверку, если текущая очередь ниже мягкого порога и нет
   перегрузки CPU/диска. Ручной degrade, высокая задержка и реальные ограничения
   governor сохраняют паузу; исключение не отключает защиту от перегрузки.
6. Нормализованный SHA-256 изображения входит в отпечаток сообщения. История
   учитывает уникальные сообщения, окно, разрешённые повторы и ревизию настроек.
   Повтор webhook не увеличивает счётчик; исходное сообщение не удаляется задним числом.
7. Подтверждённый повтор проходит существующий durable delete intent и цепочку
   объяснение/WARN/MUTE/BAN, только с включёнными в чате действиями. Перед удалением
   и санкцией повторно проверяются текущее сообщение, история, политика и иммунитет.
8. UI показывает активное сравнение изображений в составе сообщения и общий итог
   действий. Статус отдельного неактивного фотофильтра не подменяет рабочую проверку.
   При отключении основного runtime UI не обещает действующих удалений.

На проверку пары остаётся общий бюджет 30 секунд; точечное чтение MAX ограничено
5 секундами и остатком этого бюджета. Скачивания сохраняют HTTPS/host/DNS/byte
ограничения. Очередь не продлевает срок задач более существующих 10 минут.

Повреждённые и вышедшие из окна указатели заменяются новым первым вхождением.
Более старый job не перезаписывает новый указатель и не запускает действия задним числом.

## Проверяемые Инварианты

- Одна картинка без текста является полным сообщением; при допуске `0` удаляется
  вторая публикация, включая новый `photo_id` и lossless PNG/WebP с теми же пикселями.
- Чередование картинок `A, B, A, B` сохраняет оба оригинала и удаляет их повторы.
- Новая редакция одного сообщения не является новой публикацией; её время берётся
  из нормализованного event timestamp, не из сырого времени создания MAX Message.
- Повтор webhook/job, потеря кеша и сбой сохранения команды не повышают счётчик
  повторно и не создают повторную санкцию.
- Изменение содержимого, авторства, прав, иммунитета или runtime authority до
  отправки действия блокирует устаревшее действие.
- Недоступность MAX/Redis, непроверяемые вложения и превышение ограничений не являются
  доказательством совпадения. Абсолютная гарантия удаления при недоступном MAX невозможна.

`message-duplicate-flow.redis-integration.spec.ts` соединяет реальную очередь BullMQ,
Redis ordering/history, Sharp/отпечатки, enforcement и финальный guard. PostgreSQL
и MAX в нём заменены изолированными адаптерами; это не живые санкции над участниками.
API lane в CI обязательно запускает эти тесты с отдельным локальным Redis:

```sh
MAXIM_TEST_REDIS_URL=redis://127.0.0.1:6379 npm test --workspace @maxim/api -- message-duplicate
```

URL должен указывать только на одноразовый локальный Redis, не на production,
туннель к production или общую базу приложения. Тесты удаляют только свои ключи
и собственную очередь, без `FLUSHDB`/`FLUSHALL`.

## Проверка И Выпуск

- Точные фото с разными ID, PNG/WebP с одинаковыми пикселями, разные изображения.
- Отсутствующая/истёкшая ссылка, изменённые автор/сообщение/подпись/фото.
- Смешанный кеш альбома, временная ошибка источника и повтор задачи.
- Удаление, объяснение, предупреждение, ограничение и блокировка по настройкам.
- UI: MESSAGE/TEXT, выключенный фото-toggle, OFF/OBSERVE/DELETE_ONLY/FULL,
  iPhone/Android и светлая/тёмная темы.
- `npm run check:api`, `npm run check:miniapp`, production build, impact planner.
- Выпуск точного зелёного SHA во все роли общего API-образа; при изменениях UI также
  `miniapp-major-static`. Затем штатные health/static smokes. Не менять runtime control ради smoke.

См. [Message Duplicate Rollout](message-duplicate-rollout.md) для управления runtime,
остановки и совместимого отката. Данный документ не заменяет отдельные этапы допуска
похожих фото и сравнений между разными авторами.

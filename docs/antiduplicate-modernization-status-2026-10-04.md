# MAXIM: уточнение программы модернизации антидубля

Дата: 4 октября 2026 года. Дополнение к [исходному аудиту и плану](antiduplicate-modernization-plan-2026-10-04.md), baseline `1333fa9295506f2bff66df8c97cee17124931dcc`. Исходный аудит сохраняется как историческое основание. Реализованные изменения, измерения, точные SHA/CI, manifests и фактический статус выпуска собраны в [отчёте реализации](antiduplicate-implementation-report-2026-10-04.md); они не дублируются здесь изменяемыми статусами.

## Цель и неизменные условия

Устранить near-коллизии, повторную работу с фотоальбомами, бесконтрольное native-ожидание и потерю SQL cleanup после исчезновения job. Сделать пропуски объяснимыми и принять только измеренную оптимизацию. Сохранить пользовательские интерфейсы, права, расписания, точность IMAGE и порядок действий.

- История привязана к принятому оригиналу; отклонённый повтор не продлевает окно. INTERVAL/DAILY, timezone, overnight и DST сохраняются.
- Старые jobs/bindings, исчезнувшие Redis permits, отозванные права и возврат A → B → A не создают новую authority.
- Exact owner и санкционная ступень защищены от повторов; права, иммунитет, настройки и содержимое проверяются перед действием. Произвольный HTTP 404 не подтверждает удаление.
- IMAGE использует самостоятельно вычисленный canonical raster hash; URL/photoId недостаточно. Частичный альбом не даёт match или санкцию.
- Native-слот освобождается после фактического завершения либо подтверждённой смерти процесса. `Promise.race` не заменяет остановку работы.
- Телеметрия не выдаёт разрешений. Сбой диагностики не меняет результат. Проверки не отправляют сообщения и не выполняют санкции в рабочих чатах.

## Уточнения, принятые во время реализации

**R4: учёт попыток, не уникальных сообщений.** Диагностика явно `ATTEMPTS`/`BEST_EFFORT`; возможна потеря неотправленного интервала при сбое. Durable metrics ledger не добавляется. Доля завершённых поддерживаемых попыток характеризует доступную выборку, а не все логические сообщения. Удаление подтверждает receipt. `native_roundtrip` и `ordering_acquire` имеют описанные границы; перекрывающиеся интервалы не складываются.

**R2: исторические orphan не восстанавливаются по догадке.** Новая гарантия относится к новым obligations. Legacy preclaim без исходных binding/deadline не получает backfill из `createdAt`. Сохраняются fail-closed, штатный retention и возможность отдельного точного reviewed recovery. Отдельный repair CLI не включён. Неполный read-only аудит не доказывает отсутствие старых orphan.

**UI: исправлена причина нестабильного клика.** Lazy search с пустым fallback изменял геометрию между pointerdown/up. Placeholder использует действующие markup/CSS, скрыт и не принимает фокус; chat/channel сохранены. Browser helper ждёт готовность и выполняет один обычный click. Повторы клика и увеличение таймаутов не используются. Runtime gzip-стоимость измерена; запас chat additional JS до бюджета — 214 bytes.

**R6: выбран ограниченный pipeline.** MGET меняет ошибку WRONGTYPE; EVALSHA/reconnect/NOSCRIPT пока не имеют отдельного доказанного допуска. IMAGE-кандидат уже читает один ключ. Новый кеш, расширение TTL, concurrency, размеров фото и deadline не входят в поставку.

Модернизация не заменяет OCR-движок и не вводит approximate IMAGE. PDQ/pHash, OCR внутри картинок, учёт подписи/кнопок в новом режиме, составные альбомы и семантический поиск требуют отдельных продуктовых правил, opt-in, размеченных трудных отрицательных пар и оценки стоимости. GPU/LLM/векторная БД не нужны для закрытия F1–F4/R1–R3.

## Валидация, выпуск и откат

1. Локальные профильные проверки ограничены **540 секундами** и используют штатные locking wrappers. Широкий прогон нужен по impact, его успешные части без нового основания не повторяются. Exit 124 и skips отражаются явно; последующие профильные продолжения не переименовывают весь прогон в PASS.
2. Каждый runtime-выпуск требует зелёных `Required` и `Analyze JavaScript and TypeScript` точного SHA. Отдельный Docker PASS не заменяет общий допуск. После merge проверяется exact main SHA.
3. Reader/schema выпускаются раньше writer. Сохраняются queue pause/drain/exact-image fence и совместимость старых jobs/bindings/proofs. Новое evidence не интерпретирует старое proof как grant.
4. Выпускаются затронутые компоненты. Shared API обновляет все 14 ролей и предусмотренные auxiliaries; photo sandbox — второй auxiliary, не пятнадцатая роль. PostgreSQL/Redis при обычном deploy не пересоздаются.
5. После strict smokes настроено **600 секунд наблюдения**, фактические начало/конец записываются с учётом финальных probes. Результаты OCR recycle, critical samples и ресурсные warnings сохраняются честно. Десять минут не доказывают DAILY/DST/retention; эти свойства проверяются управляемым временем.
6. Immutable rollback выбирается по source floor и применённым миграциям. Старый unsafe near запрещён даже при выключенном control. Для checkpoints подтверждён CFE manifest; v2 partial proofs недоступны v1 reader. Native wrapper останавливает consumer до смены auxiliary, проверяет image/isolation/UDS hash и лишь затем снимает fence. Claims/counters не сбрасываются ради replay.
7. При ложном действии, ожившем отзыве, повторной санкции либо освобождении чужого owner остановить этап штатным revision-checked control. Использовать совместимый `rollback-release`; если безопасного target нет, оставить ограничение функции и исправлять вперёд.

Программа закрывается по реализованным критериям, exact-SHA CI, отдельным принятым выпускам, доступным совместимым manifests и честным ограничениям измерений. Необязательные кандидаты без подтверждённого выигрыша остаются отдельными будущими задачами.

Отдельное последующее улучшение: сохранять ограниченный код причины и время native recycle без содержимого изображений или пользовательских идентификаторов. После заключительного выпуска фотообработчик восстановился и прошёл повторный isolation/UDS hash smoke, но причину одного перезапуска из имеющихся логов установить не удалось.

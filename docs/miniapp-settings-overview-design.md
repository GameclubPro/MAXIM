# Главные экраны настроек: мобильная композиция без лишнего текста

Дата: 23 октября 2026. Статус: мобильная компоновка реализована; сценарии
локальной приёмки перечислены ниже. CI, выпуск и приёмка в физическом MAX
подтверждаются отдельно по фактическим результатам.

Область: смартфонные каталоги настроек чата и канала Майора, общих настроек
сетки и навигационные пункты модулей Публика. Вложенные редакторы, списки постов,
результаты операций и статистика имеют собственную информационную структуру.
Настольную компоновку этим этапом не переделывать.

Этот документ заменяет прежние предложения показывать сводку и обычное состояние
у каждого пункта настроек. Требование закреплено также в
[инструкциях мини‑аппа](../apps/miniapp/AGENTS.md). Его нельзя отменять под видом
улучшения информативности, доступности, «умных карточек» или визуальной полировки.

## 1. Обязательное правило

**У навигационного пункта только иконка, название раздела и стрелка перехода.**

Под названием, рядом с ним и в отдельной нижней строке не должно быть:

- описания функции, инструкции или пояснения;
- сводки настроек: «Разрешено: 2», «Активных ограничений: 2», «Удаление · баланс»;
- счётчика: «2 чата/канала», числа правил, слов, источников или получателей;
- обычного статуса: «Включено», «Выключено», «Настроено», «Не проверено»;
- точки, плашки или мини-переключателя, заменяющих эти подписи.

Не оставлять такие копии в DOM ради скрытия через CSS, `sr-only`, `opacity: 0`,
высоту `1px`, обрезание или добавление в `aria-label`. У навигационного элемента
доступное имя совпадает с названием; роль и действительные `disabled`/`expanded`
состояния передаются семантически. Поисковые синонимы можно сохранить в индексе,
не выводя их как описание результата.

Полные состояния, параметры, числа, помощь и инструкции доступны **после открытия
раздела**, возле соответствующего управления. Их не удаляют из редакторов.
Никаких новых запросов к API для украшения каталога.

Это правило относится к пунктам навигации. Имя сообщества, названия групп,
поисковое поле и подписи настоящих действий остаются. Реальная ошибка загрузки,
доступа или сохранения не исчезает: ей положен один контекстный блок с действием,
а не постоянная подпись под каждым модулем. Ошибка отдельного модуля остаётся
внутри него и в существующем механизме уведомления о неуспешном сохранении.

## 2. Выбранная композиция

Основа — **одна колонка сгруппированных строк**, объединённых общей поверхностью.
Каждый пункт больше не выглядит отдельной высокой карточкой. Плитки в две колонки,
карусель и отдельная «главная карточка» над каталогом в этот этап не входят.

```text
┌─────────────────────────────────┐
│ [аватар] Название сообщества     │
│ [Боты]             [Статистика] │
│                                 │
│ [⌕ Найти настройку           ×] │
│                                 │
│ Защита                          │
│ ┌─────────────────────────────┐ │
│ │ [иконка] Ссылки           › │ │
│ │          ───────────────── │ │
│ │ [иконка] Ограничения      › │ │
│ │          ───────────────── │ │
│ │ [иконка] Подписка         › │ │
│ └─────────────────────────────┘ │
└─────────────────────────────────┘
```

Порядок сверху вниз:

1. Аватар и имя текущего сообщества. Длинное имя переносится; рядом нет второго
   заголовка «Настройки чата», «Управление» или рекламной фразы.
2. Действительные контекстные действия «Боты» и «Статистика» при их доступности.
   Они компактнее основных строк. Не добавлять неподдерживаемые действия.
3. Одно поле поиска с понятным placeholder, очисткой и возвратом фокуса.
   Нет вводного абзаца, статистики поиска и постоянной подсказки под полем.
4. Группы настроек. Сохранить существующие состав, порядок и поисковые синонимы;
   не переименовывать и не переносить функции ради новой вёрстки. У группы только
   короткое название, без описания и счётчика. После фильтра пустая группа скрыта.

Сетка сохраняет реальную область применения один раз в контексте экрана;
повторять её в каждом пункте нельзя. Редактор и финальная проверка по-прежнему
явно показывают, кого затронет изменение. В Публике действующий выключатель
подключения остаётся отдельным рабочим контролом; у входов в модули его не дублируют.

Существующую нижнюю навигацию сохранить. Последняя строка полностью прокручивается
выше неё с учётом измеренной нижней зоны; нельзя просто прибавить safe area дважды.
При поиске и открытой клавиатуре контент остаётся доступным. Если действующая шапка
закреплена, она компактна и не занимает большую часть короткого экрана; дополнительную
закреплённую панель фильтров или заголовков групп не вводить.

## 3. Визуальная спецификация

| Элемент           | Решение для прототипа и проверки                                                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Внешняя геометрия | 12 px по бокам на 320 px, 16 px на обычном смартфоне. Одна колонка на всей смартфонной ширине.                                                     |
| Группа            | Общая поверхность с радиусом около 20 px, мягкой границей и умеренной глубиной. Между группами 20–24 px. Без нескольких вложенных рамок.           |
| Строка            | Минимум 64 px, вертикальные поля 12 px. Высота растёт с названием и размером текста; жёсткого `height` нет. Вся строка — одна зона перехода.       |
| Иконка            | Согласованный контурный набор 20–22 px в ячейке 38 px без видимой подложки. Цветной сам значок; один размер внутри семейства. Не отдельная кнопка. |
| Название          | Manrope, ориентир 16 px и вес 600–650. Полный текст, перенос без многоточия; две строки при обычном размере и больше при необходимости.            |
| Стрелка           | Одинаковый размер и правая ось, спокойный контраст, не отдельная кнопка и не переключатель. `aria-hidden` у декора.                                |
| Разделитель       | Тонкий, с отступом до оси названия. Не проходит сквозь иконку; после последней строки отсутствует.                                                 |
| Заголовок группы  | Около 13 px, умеренная насыщенность, обычный регистр. Без капслока, порядкового номера, декоративной линии и описания.                             |
| Поиск             | 46–48 px, радиус 14–16 px, одна граница; очистка имеет эффективную зону минимум 44×44 px.                                                          |

Цифры — исходные параметры, а не повод подрезать длинный текст. При 150/200%
текста читаемость важнее плотности и точного количества строк на первом экране.

У Майора — графит и четыре неоновых оттенка самих иконок: синий для навигации,
индиго для контента и управления, розовый для защиты, охра для специальных
инструментов. Не сводить все значки к одному синему и не возвращать цветные
подложки. В тёмной теме допустимо короткое слабое свечение только контура SVG;
в светлой — глубокие читаемые оттенки без свечения. Цвет обозначает смысл модуля
и не меняется от включения, выключения или ошибки; подпись канала всегда синяя.
Текст, стрелки и общие поверхности остаются нейтральными. У Публика та же геометрия:
оранжевый бренд и основные действия, разные согласованные цвета значков. Комментарии,
входящие предложения и автоответы различаются также силуэтом значка: диалог,
входящий конверт и ответная стрелка. Ни лайма, ни зелёной маркировки всех включённых
разделов.

В светлой теме глубину создают тон поверхности, тонкая граница и мягкая тень;
в тёмной — различимые уровни графита и спокойный светлый контур. Не затемнять
текст ради «дорогого» вида. Без стекла под списком и тяжёлого размытия при скролле.

Pressed меняет фон строки; focus-visible охватывает её целиком и не обрезается
скруглением группы. Короткая обратная связь 120–160 ms не сдвигает геометрию.
Без подпрыгивания, stagger появления каждой строки и анимации высоты при возврате.
`prefers-reduced-motion` отключает необязательное движение.

## 4. Состояния и взаимодействия

- Открывается вся строка с первого нажатия. Нажатия на значок и стрелку ведут
  туда же; вложенных кнопок и переключения модуля из каталога нет.
- Back закрывает текущий слой, сохраняет черновик по существующей модели и
  возвращает позицию, фокус и запрос поиска. В MAX нет второй большой Back-кнопки.
- После сохранения возврат не добавляет подпись «Сохранено» к пункту, не меняет
  высоту строки, порядок или цвет всей группы. Ошибка сохранения остаётся заметной
  в редакторе; существующее уведомление не подменяется молчаливым уходом в каталог.
- Loading сохраняет форму будущих строк: один плейсхолдер иконки и названия,
  без плейсхолдера описания. Refresh не заменяет уже читаемый каталог.
- Пустой поиск показывает одно состояние с действием «Сбросить поиск»; без
  повторяющихся советов у каждой группы. Очистка возвращает фокус в поиск.
- Ограничения доступа сохраняют действующие guards. Недоступный раздел не
  маскируют под выключенный. Причина доступна через существующий экран/панель
  доступа или единое состояние экрана; запрет не обходят ради красивой строки.
- Для сетки отсутствие aggregate-данных не превращается ни во «Включено», ни
  в «Не проверено» под названием: в каталоге обычных статусов вообще нет.
  Смешанные, неизвестные и недоступные значения честно различаются в редакторе.
- Сохранить действующие маршруты, ключи поиска, порядок функций, границы прав,
  назначение ботов и API. Desktop не получает эти мобильные overrides.

| 5. Финальная приёмка | Сравнение с прежними карточками на одинаковых данных; записаны оценки, результаты проверок и ограничения.                                                      | Выбранные focused проверки, штатный агрегат, точные CI-gates и выпуск только затронутого UI.          |

Для защиты от повторения ошибки при реализации нужен один focused regression
настоящего каталога: у навигационного пункта единственный видимый текст — название,
нет элементов описания/обычного статуса/счётчика и скрытых копий, переход работает.
Проверка параметризуется по чату, каналу, сетке и Публику; она не требует равенства
всего `textContent` страницы или запрета пояснений внутри редактора. Дополнительно
проверяется отсутствие старых требований показывать summary в затронутых тестах.

## 6. Что означает «10 из 10» для этого среза

Каждый пункт оценивается 0–2. Самооценка не заменяет подтверждённые проверки.

| Критерий               | Условие для 2 баллов                                                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Отсутствие шума        | На всех четырёх семействах в пункте только иконка, название, стрелка. Нет исключений ради описаний и обычных статусов.               |
| Композиция             | Цельная группа, ясные оси и ритм; длинные названия выглядят естественно, пустые группы отсутствуют, шапка не конкурирует со списком. |
| Визуальный характер    | Обе темы выразительны и читаемы; Major/Publik узнаваемы, акценты согласованы, нет набора пёстрых высоких карточек.                   |
| Работа на смартфоне    | Touch, 200% текста, поиск/клавиатура, Back, фокус, черновики и нижний край проверены; нет обрезания и пересечений.                   |
| Подтверждение качества | Приложены реальные снимки до/после, green проверки и честные ограничения; мобильная native-приёмка отделена от браузерных профилей.  |

Любое описание, сводка, счётчик или обычный статус у пункта означает **срез не
принят**, независимо от суммы баллов. Оценку после написания плана не выставлять:
сначала реализовать, сравнить реальные экраны и проверить сценарии. Физический
MAX, нативная клавиатура и экранные дикторы остаются отдельной приёмкой, пока
соответствующих наблюдений нет.

## 7. Реализация и защита правила

Мобильные пункты общего компонента, рекламной площадки и профиля биржи не создают
описаний и обычных состояний в DOM. Данные для поиска остаются в индексе.
Постоянные обёртки групп сохраняют редакторы при смене ширины; на desktop они
используют `display: contents`. Пустые группы скрываются вместе с заголовком,
а разделитель отсутствует после последней видимой строки.

В Публике предложения открываются отдельной панелью с прежними тремя
переключателями и проверкой ревизии. Рабочий переключатель подключения Публика
сохранён отдельно. Узкий фильтр VK на 320 px переносится в две строки.

Регрессии для последующих изменений:

- `apps/miniapp/test/settings-overview-navigation.browser.mjs` проверяет реальные
  пункты шести каталогов: чат, канал, сетки чатов и каналов, оба каталога Публика.
  Проверки включают отсутствие скрытых копий, точное доступное имя, touch, Back,
  фокус, прокрутку, поиск, 200% текста и сохранение черновика при 599→601→599 px.
- `settings-search-layout.browser.mjs` защищает поиск при задержанной загрузке,
  очистку, пустые результаты и настольную компоновку.
- `publisher-comments.browser.mjs` проверяет мобильную геометрию и сохранение,
  ошибку, повторное открытие и фокус панели предложений; desktop сохраняет
  прежние встроенные переключатели.
- `marketplace-profile.browser.mjs` проверяет чистое название пункта биржи и
  рабочий редактор после открытия, включая состояния доступа и сохранение.
- Штатный capture проверяет все реальные элементы каталогов, поэтому отсутствие
  маркера проверки не позволяет пропустить шумный пункт.
- `settings-mobile-layout.browser.mjs` проверяет полное длинное название сообщества,
  очистку и пустой поиск при 200% текста, доступность последнего пункта над навигацией.
- `action-confirm-sheet.browser.mjs` проверяет подтверждения на коротком экране,
  при смещённой клавиатурой видимой области и 200% текста; `time-field-keyboard.browser.mjs`
  проверяет выбор времени с шагом минут и сохранение исходного значения при отмене.
  Эти три сценария запускаются с `MINIAPP_TEST_BASE_URL` локального Vite-сервера.

Браузерная приёмка охватывает Chromium и WebKit, обе темы и ширины 320/393/412 px;
дополнительно Публик проверяется на 280 px. Это не свидетельство проверки
физического клиента MAX, нативной клавиатуры или экранного диктора. Возвращать
подписи в каталог ради этих непроверенных сред запрещено тем же правилом раздела 1.

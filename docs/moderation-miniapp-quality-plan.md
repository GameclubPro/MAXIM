# Качество мини-приложения модерации

## Границы

Профиль модерации: список чатов и каналов, настройки защиты, участники,
история модерации, статистика и связанные диалоги. Публикации и VK принадлежат
отдельному профилю Publik и не входят в эту работу. Решения о правах доступа
и выполнении модерации остаются на сервере.

## Обнаруженные проблемы

- Каталог скрывал краткие состояния настроек: для проверки защиты требовалось
  открывать разделы по очереди.
- «Мут», «бан», «иммунитет», внутренние идентификаторы и подписи вроде ERR48
  требовали от обычного пользователя технических знаний.
- Инфоподсказки не закрывались касанием вне, Escape или отдельным нажатием
  «Назад». Длинная подсказка могла оказаться выше доступной области экрана.
- Массовое применение допускало подтверждение с результатом проверки старого
  выбора чатов. Во время применения оставались доступными изменения выбора.
- Подтверждение действия из истории исчезало до завершения запроса, поэтому
  состояние выполнения и ошибка теряли связь с выбранным действием.
- Редактор защиты участника позволял менять параметры во время сохранения,
  а при обновлении данных того же участника мог открывать устаревшие значения.
- Проверка размеров сенсорных кнопок охватывала публикации, но не модерацию.

## Реализация

1. Каталог настроек: показывать краткое текущее состояние под названием,
   сохранять читаемую плотность списка и размер основных кнопок от 44 px.
2. Понятный язык: называть действия по результату; подробности, ограничения
   и исключения раскрывать в инфокнопках. Не показывать внутренние ID и ошибки.
3. Подсказки: учитывать доступную область и клавиатуру, ограничивать высоту,
   поддерживать прокрутку. Сначала закрывать подсказку, затем её родительский
   экран; не перехватывать закрытие верхнего подтверждения.
4. Настройки: подтверждать только актуальный выбор получателей, показывать
   их названия, явно учитывать сохранение исходного чата. Блокировать
   параллельное применение и межсекционные сохранения.
5. Участники: готовые сроки ограничений, полные понятные подписи, актуальные
   начальные значения защиты, сохранение уже начатого черновика при обновлении
   данных, неизменяемые параметры на время запроса.
6. История: сохранять подтверждение до результата запроса, показывать
   выполнение на выбранном действии, оставлять ошибку рядом с подтверждением.
7. Проверка спама: нейтральное название, раздельные решения о признаках спама
   и блокировке; оценка не объявляется доказательством или вероятностью.
8. Визуальные регрессии: основные экраны, пустые состояния, ошибки, инфокнопки,
   подтверждения, поиск, списки, календарь и переходы между профилями.

## Критерии Приёмки

- Проверки типов, тесты мини-приложения, архитектура CSS и production-сборка
  проходят без увеличения установленных бюджетов.
- На iPhone SE, Android и компьютере нет горизонтального переполнения,
  обрезанных подписей и недоступных основных действий; обе темы читаемы.
- Подсказки не меняют настройку; закрытие подсказки не закрывает её экран.
- Во время запроса нельзя повторить действие или изменить его параметры.
- Ни данные другого профиля, ни незакоммиченные изменения Publik не входят
  в scoped-релиз модерации.
- Развёртывается только `miniapp-major-static` после обязательных проверок
  точного коммита; выполняются штатные проверки `/app/`.

- `git diff --check` для файлов этой работы; staged-only проверка перед релизом.

# Публик: аудит и план качества

## Границы проверки

Проверяются кабинет Publisher, публикации и VK-автопостинг. Major-публикации остаются
отключенными. Safety Desk, правила модерации, реальные пользовательские материалы и
настройки чужих чатов не меняются. Секреты и персональные данные в отчет не включаются.

Production-проверки health и publisher-dispatch-status подтверждают доступность
компонентов, но не доказывают доставку конкретного поста. Визуальные сценарии используют
локальный preview transport. Полный перебор всех дефектов и объективная оценка
«топового уровня» невозможны; ниже перечислены проверяемые критерии.

Дополнительно исправлены разбор дат сохраненного расписания в зоне устройства,
окончание последнего дня раньше 23:59, исключение при очистке даты очереди,
drag-only быстрые слоты, зависимость переключателей от CSS старых настроек
и подмена полного счетчика очереди длиной ограниченного списка.

Существующие сильные стороны сохраняются: серверная пагинация, exact Publisher
access, изоляция ботов, сохранение черновиков, ревизии контента, явная обработка
AMBIGUOUS без автоматической повторной отправки, отсечение истории VK при включении,
повторная проверка политики перед отправкой и native BackButton.

## Следующие продуктовые этапы

Это отдельный backlog, а не обещание возможностей, которых еще нет в API.

1. Серверный preview повторов: ближайшие 5-10 запусков, фактическая IANA-зона,
   DST и конфликты получателей. Один движок расчета для preview и dispatch;
   не дублировать серверное расписание в браузере. Приемка: даты preview совпадают
   с созданными occurrences, включая DST, границы недели и лимит запусков.
2. Единая операционная лента: причина ожидания, последний успешный sync, время
   следующей попытки и ручная проверка неопределенной доставки. Нужен ограниченный
   серверный read model; нельзя собирать метрики загрузкой всех страниц.
3. Атомарное массовое изменение произвольных параметров источников с expectedRevision,
   preview различий и журналом. Текущие последовательные PATCH могут частично пройти;
   интерфейс обязан обновить фактическое состояние после ошибки.
4. Редакционный календарь с переносом времени, проверкой конфликтов и подтверждением
   затронутых получателей; библиотека шаблонов и серверные черновики между устройствами.
5. Роли редактор/согласующий, история версий и восстановление контента. Нужны отдельные
   правила доступа, а не клиентское скрытие кнопок.
6. Контроль качества по данным: SLO задержки публикаций, доля ручных проверок,
   ошибки медиа и доступов, успешность сценария создания. Без содержимого постов,
   токенов и идентификаторов пользователей в телеметрии.

## Проверка и выпуск

- Unit/regression: применение пресетов, статусы, временные окна, числовые drafts,
  уникальность времен и резюме повторов.
- API, Prisma, miniapp, CSS ownership, линтер, refactor guards, production bundle budgets.
- Playwright: iPhone SE, Android и desktop, light/dark, раскрытые параметры,
  подтверждение пресета, ошибки, навигация, прокрутка и клавиатура.
- Scoped release через exact-SHA CI gates: общий API образ со всеми ролями и
  miniapp-major-static; добавление уже используемого Luxon в зависимости miniapp
  меняет корневой lockfile, поэтому классификатор также включает admin-static.
  Postgres/Redis не пересоздаются. Luxon и редактирование очереди загружаются лениво;
  действующие бюджеты сборки не увеличиваются.
- Live отправка допустима только в закрепленные тестовые сущности после проверки
  их exact Publisher binding; отсутствие авторизованной сессии не обходится.

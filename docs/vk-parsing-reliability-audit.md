# VK-парсинг: надёжность и производительность

Дата ревизии: 2026-09-17. Дополняет исторический [аудит 2026-08-29](vk-parsing-optimization-plan.md).

## Область проверки

Проверены Publisher HTTP routes, авторизация, клиент мини-приложения, сборка ленты,
VK HTTP transport, Redis limiter/метрики, определение источника, sync/lease,
проверка отсутствующих постов, импорт, медиа-кеш, маршрутизация публикации,
сохранение намерений и существующие регрессионные тесты.

Скриншот показывает ошибку загрузки ленты, а не результат `wall.get`. По нему
нельзя установить конкретный сетевой сбой. В ограниченной выборке production-логов
есть HTTP timeouts/aborts, но URL редактируются, поэтому привязка этих записей
именно к VK не доказана. Приведённые ниже дефекты подтверждены кодом и тестами.

## Совместимость и безопасность

- Миграции БД и изменения shared contracts не требуются. Nullable diagnostics и
  пустой audit list уже разрешены контрактом; активный экран их не использовал.
- Старые Redis v1 metrics не мигрируют и истекают по прежнему TTL. Новое окно
  заполняется после deploy; краткий прогрев метрик не является потерей постов.
- Никакие источники, посты, очереди публикации, настройки пользователей или
  сообщения MAX этим исправлением не удаляются и не включаются автоматически.
- Точный Publisher scope, baseline, первый sync без автопоста, MAX receipt-first
  recovery и карантин неоднозначных отправок сохранены.
- `getById` остаётся read-only. Сбой любой пачки отменяет вывод об отсутствии
  всей проверяемой группы, включая ранее успешно обработанные пачки.

## План проверки и доставки

1. Регрессионные тесты: задержка тела ответа, общий deadline, HTTP HTML errors,
   malformed envelope, auth/captcha failures, 205 ID, частичный отказ пачки,
   source identity, предел Redis window, граница limiter, лёгкая лента и UI errors.
2. `npm run check:api`, `npm run check:miniapp`, production miniapp build,
   static/refactor/docs checks и мобильные screenshots локальной сборки.
3. Staged-only commit/push; точные успешные `Required` и
   `Analyze JavaScript and TypeScript` для выбранного SHA.
4. Deploy `api-shared` и `miniapp-major-static` штатным wrapper; все API roles
   одной версии, без пересоздания Postgres/Redis и без CDN/app2.
5. Штатные live/ready/static/OCR smokes и ограниченная read-only проверка логов.

## Оставшиеся ограничения

- В ограниченной выборке отказы `PublisherSetupRequiredException` имели причину
  `policy_disabled`: Публик выключен политикой сущности. Это ожидаемая блокировка
  до отправки в MAX, а не ошибка VK или разрешение обойти настройки пользователя.
  В этой работе отключённые подключения не включаются.
- Видео без прямого HTTPS MP4, документы, опросы и полное воспроизведение репостов
  по-прежнему не гарантируются. Это отдельная работа над точностью переноса
  контента, не основание незаметно менять опубликованные записи.
- Лимит страниц sync ограничивает импорт истории. Бесконечный backfill не добавлен.
- Offset pagination стабилизирована для одинаковых дат, но при поступлении новых
  постов возможны сдвиги страниц. Keyset pagination потребует отдельного изменения
  API/клиента; она не нужна для исправления стартовой загрузки.
- Операционный `/summary` остаётся более тяжёлым диагностическим запросом.
  Не возвращать его, глобальные media aggregates или audit scans в polling ленты.
- Доступ к документации `dev.vk.com` из среды проверки вернул HTTP 418.
  Лимит 100 ID проверяется по закреплённой интеграции и регрессионным тестам;
  актуальная внешняя доступность конкретного сообщества требует его URL и прав.

Проверки не доказывают отсутствие всех возможных ошибок VK/MAX и не заменяют
наблюдение за пользовательским сценарием после доставки.
